# Andrade Ángel — Personal Portfolio

A personal portfolio website built with **HTML, CSS, and Vanilla JavaScript** to showcase my projects, technical skills, and ongoing journey in software development.

The project demonstrates practical front-end development skills, with a focus on DOM manipulation, interactive UI components, responsive design, and JavaScript functionality without relying on front-end frameworks.

🌐 **Live Website:** [andradeangel.com](https://andradeangel.com/)

## ✨ Features

* **Responsive Design** — Layout adapted for desktop and mobile devices.
* **Interactive Navigation** — Dynamic navigation and UI interactions using JavaScript.
* **Project Filtering and Pagination** — Browse projects by category with dynamically generated pagination.
* **Skills Showcase** — A dedicated section highlighting technologies and tools.
* **Contact Form** — Send project inquiries and messages through EmailJS.
* **Secret Message Feature** — A small interactive feature connected to a Cloudflare Worker and Telegram.
* **Dynamic UI Updates** — DOM manipulation, event handling, and interactive elements built with Vanilla JavaScript.
* **Visual Effects** — Custom styling, transitions, and animations to enhance the user experience.

## 🛠️ Technologies

* **HTML5** — Semantic page structure and form elements.
* **CSS3** — Responsive layouts, styling, transitions, and animations.
* **JavaScript (Vanilla JS)** — DOM manipulation, event listeners, interactive components, and application logic.
* **EmailJS** — Contact form integration.
* **Cloudflare Workers** — Backend functionality for the secret message feature.
* **Telegram Bot API** — Message delivery for the secret message feature.
* **Git and GitHub** — Version control and project hosting.
* **GitHub Pages / Custom Domain** — Website deployment.

## 🔒 Security Considerations

* The repository is public, so client-side code and configuration identifiers are visible by design.
* EmailJS client-side integrations use a public key. Private credentials and service tokens should never be committed to the repository.
* Contact form protection should include appropriate domain restrictions and rate limiting.
* The Cloudflare Worker should validate incoming requests, apply suitable abuse-prevention controls, and keep private credentials in Cloudflare secrets.
* Client-side validation improves usability but should not be treated as a security boundary.
